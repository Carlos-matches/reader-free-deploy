# 🎯 混合方案：免费前端 + 免费后端（推荐）

> 这个方案把你的**原始想法（用 Netlify）和免费服务器结合起来**，
> 是绕开「Netlify 跑不了服务器」这个限制的最佳办法。

---

## 为什么这样拆分？

你最初想用 Netlify —— 方向没错，只是**放错了东西**：

```
❌ 错误：Netlify 放整个 reader 服务器
   → 跑不了（需要常驻进程 + 数据库）

✅ 正确：Netlify 放前端网页（纯静态文件）
        Silly Development 放服务器（Node.js + 数据库）
```

reader 官方**明确支持**这种前后端分离部署。源码 `cors.ts` 的注释原文：

> "Three deployments have to work... **2. H5 served from somewhere else (a static host, a dev server on :5174)** against a LAN server at an IP the client cannot know in advance."

也就是说：**前端放 Netlify 是官方支持的用法**，不是 hack。

**两边都免费，都不需要绑卡**（Netlify 也不需要信用卡）。

## 第 1 步：部署后端（免费服务器）

先按 👉 [免绑卡部署.md](./免绑卡部署.md) 把后端跑起来。

完成后你会得到一个地址，形如：
```
http://xxx.sillydev.co.uk:12345
```

**记下这个地址**，下一步要用。

同时记下你在后端设置的环境变量 `DATA_DIR=.`

---

## 第 2 步：构建并部署前端到 Netlify

### 2.1 本地构建前端

需要有 [Node.js 22+](https://nodejs.org/)：

```bash
# 拉源码
git clone https://github.com/hectorqin/reader.git
cd reader

# 编译前端（H5 客户端）
cd web
npm ci
npm run build
```

构建产物在 `web/dist/` 目录。

### 2.2 部署到 Netlify

**方式 A：拖拽上传（最简单）**

1. 打开 <https://app.netlify.com/drop>
2. 把 `web/dist` 文件夹**整个拖进去**
3. 几秒后得到一个地址，形如 `https://random-name-123.netlify.app`
4. 可以到 Site settings 改成好记的名字

**方式 B：连接 Git 仓库（可自动更新）**

1. 把 `web/dist` 推到 GitHub
2. Netlify → Add new site → Import from Git
3. 构建设置：Build command 留空，Publish directory 填 `dist`（或你的目录名）

---

## 第 3 步：让前后端互通（关键）

### 3.1 在后端设置允许的前端来源

回到免费服务器的环境变量，添加：

| 变量名 | 值 |
|---|---|
| `CORS_ORIGINS` | 你的 Netlify 网址，例如 `https://your-site.netlify.app` |

> 多个来源用**英文逗号**分隔，例如：
> `https://your-site.netlify.app,https://reader.example.com`

**重启服务生效。**

### 3.2 在前端填入后端地址

打开你的 Netlify 网址，首次进入时会让你填**服务器地址**：

```
http://xxx.sillydev.co.uk:12345
```

填进去后即可注册/登录。

> 💡 **地址会保存在浏览器里**，每台设备填一次即可。
> 手机上也一样：打开 Netlify 网址 → 填服务器地址 → 添加到主屏幕。

---

## 第 4 步：加 HTTPS（可选但推荐）

后端是纯 HTTP（免费主机不提供证书），会有两个后果：

1. 浏览器可能提示"不安全连接"
2. **Netlify（HTTPS）调用 HTTP 后端可能被浏览器拦截**（混合内容限制）

### 解决方案：Cloudflare Tunnel（免费）

把 HTTP 后端包装成 HTTPS：

```
1. 注册 Cloudflare（免费，不需信用卡）→ 添加你的域名
2. Zero Trust → Networks → Tunnels → Create a tunnel
3. 安装 connector 到你的免费服务器（或用面板的 Scheduled tasks 运行）
4. 配置 Public Hostname:
     Subdomain: reader
     Domain:    你的域名.com
     Service:   http://localhost:你的端口
5. 保存后就有 https://reader.你的域名.com
```

然后把后端的 `CORS_ORIGINS` 保持为 Netlify 地址，前端填**新的 HTTPS 后端地址**。

> 没有域名也可以用 Cloudflare 的 `trycloudflare.com` 临时隧道测试（地址每次会变，不适合长期使用）。

## ⚠️ 常见问题

<details>
<summary><b>前端打开后一直转圈 / 报跨域错误？</b></summary>

按顺序检查：

1. **`CORS_ORIGINS` 填对了吗？** 必须是完整的来源，含 `https://`，**结尾不要加 `/`**
   - ✅ `https://your-site.netlify.app`
   - ❌ `https://your-site.netlify.app/`
   - ❌ `your-site.netlify.app`

2. **改完变量重启服务了吗？** 环境变量需要重启才生效

3. **后端还活着吗？** 直接访问 `http://后端地址/api/v1/health`，应该返回 JSON

4. **混合内容被拦了吗？** 打开浏览器 F12 控制台，如果有
   `Mixed Content: The page at 'https://...' was loaded over HTTPS, but requested an insecure resource 'http://...'`
   说明需要按第 4 步加 HTTPS
</details>

<details>
<summary><b>Netlify 真的免费吗？会要信用卡吗？</b></summary>

Netlify 免费套餐（Starter）：
- ✅ **不需要信用卡**
- ✅ 每月 100GB 流量、300 分钟构建时间
- ✅ 自带 HTTPS 和 CDN
- ✅ 支持自定义域名

前端是纯静态文件，几百 KB，**完全用不完**。
</details>

<details>
<summary><b>能不能不用命令行，全在网页上做？</b></summary>

前端部分可以（拖拽上传）。但后端**必须先本地编译**，因为：
- 免费主机没有 Docker
- 官方只发布源码，不发布编译产物

所以 `build-bundle.sh` 这一步省不掉。只要装个 Node.js，跑一条命令就行。
</details>

<details>
<summary><b>这样比单机 All-in-One 好在哪？</b></summary>

| | 前端 Netlify + 后端免费主机 | 只用免费主机 |
|---|---|---|
| 界面 | ✅ 完整 H5，HTTPS，CDN 加速 | ❌ 只有 API，需自行编译前端 |
| 磁盘占用 | ✅ 前端不占服务器 512MB | ❌ 前端会吃掉不少空间 |
| 访问速度 | ✅ 全球 CDN | ⚠️ 取决于服务器位置 |
| 复杂度 | ⚠️ 要配 CORS | ✅ 简单 |

**推荐用混合方案**，体验最好，而且正好用上你想要的 Netlify。
</details>
