## ⚠️ 必须知道的两个限制

官方条款原文：

> **we do not provide a domain name or an HTTPS certificate for it**."

意味着你只能通过 `http://IP:端口` 访问。**解决方案**：用 Cloudflare Tunnel 套一层免费 HTTPS（见下文）。

### 2️⃣ 无备份

官方原文："it is the only copy there is."

**必须自己定期下载 `/data` 备份**（见下文）。

## 📋 部署步骤

### 第 1 步：本地构建部署包

免费主机**没有 Docker**，而官方只发布源码（不发布编译好的文件），所以要在你电脑上编译一次。

**前提**：装好 [Node.js 22+](https://nodejs.org/) 和 [Git](https://git-scm.com/)

```bash
cd scripts
bash build-bundle.sh
```

约 2～3 分钟后生成 `reader-bundle.zip`。

### 第 2 步：注册 Silly Development

1. 打开 <https://sillydev.co.uk/> → **Create account**
2. 用邮箱注册（**不需要银行卡**）
3. 进入面板 → **Create server**
4. 运行时选 **Node.js**
5. 内存/磁盘用默认的免费额度

### 第 3 步：上传文件

**方式 A：File Manager（简单）**
1. 面板 → **Files** → **Upload**
2. 上传 `reader-bundle.zip`
3. 右键 → **Unzip**
4. 确认 `dist/`、`node_modules/`、`package.json` 在根目录

**方式 B：SFTP（快，推荐）**
1. 面板找到 SFTP 连接信息（主机、端口、用户名、密码）
2. 用 FileZilla / WinSCP 连接
3. 把解压后的**文件**（不是文件夹）拖到根目录

### 第 4 步：配置启动和环境变量

**Startup / 启动文件**：
```
dist/main.js
```

**环境变量**（Environment Variables）：

| 变量名 | 值 |
|---|---|
| `DATA_DIR` | `.` |
| `BOOKS_DIR` | `books` |
| `PORT` | 面板显示的端口（通常是 `PORT` 变量，平台会自动注入）|
| `READER_TOKEN_SECRET` | 自己生成的随机字符串（≥16 位）|
| `ALLOW_REGISTRATION` | `false` |

> 💡 生成随机密钥（PowerShell）：
> ```powershell
> -join ((48..57)+(65..90)+(97..122) | Get-Random -Count 48 | % {[char]$_})
> ```

### 第 5 步：启动

点 **Start**，看 Console 日志。出现类似下面就是成功了：

```
server listening at http://0.0.0.0:XXXX
```

然后在面板 **Ports / Network** 里找到分配的地址（形如 `http://xxx.sillydev.co.uk:12345`）。

用这个地址访问即可注册第一个管理员账号。

## 🔒 加 HTTPS（推荐）

因为没有 HTTPS，建议用 **Cloudflare Tunnel** 免费加一层（顺便还能用自定义域名）：

```bash
# 在服务器上（或用 Cloudflare 的 Zero Trust 面板操作）
# 1. 注册 Cloudflare，添加你的域名
# 2. Zero Trust → Networks → Tunnels → Create tunnel
# 3. 指向 http://localhost:你的端口
# 4. 绑定一个子域名，例如 reader.你的域名.com
```

这样就有了 `https://reader.你的域名.com`，且**完全免费**。

---

## 💾 备份数据（重要！）

数据都在服务器的 `dist/../data` 目录（即 `DATA_DIR` 指向的位置）。

**手动备份**：面板 → Files → 找到数据库文件 → Download

**自动备份**：面板有 **Scheduled tasks** 功能，可以设置定时任务，例如：
```
tar czf backup-$(date +%F).tar.gz data/
```
然后用脚本通过他们免费的 REST API 下载。

> ⚠️ 官方明确说不保证备份，**请务必自己定期备份**。

## ❓ 常见问题

<details>
<summary><b>256MB 内存够吗？</b></summary>

**勉强够。** reader 的服务端依赖很轻（fastify + 几个解析库，都是纯 JS），实测内存占用不高。

但要注意：
- ❌ **不要启用影音/媒体库功能**（需要 ffmpeg，会爆内存）
- ⚠️ 书库扫描大目录时可能变慢
- ✅ 日常阅读、搜索书源完全够用
</details>

<details>
<summary><b>Web 界面（H5）在哪里？</b></summary>

`build-bundle.sh` 只打包了**服务端**（因为 512MB 磁盘放不下前端构建产物）。

服务端的 `/api` 接口完全正常，但直接用浏览器打开根路径看不到界面。三个选择：

1. **推荐**：把前端托管到 Netlify（前端是纯静态文件，Netlify 完全胜任），然后在 reader 设置里配置 CORS 来源
2. 用 Android App（Legado）连接，不需要网页界面
3. 自己编译前端并上传（需要更多磁盘空间）

**注意**：这正好用上了 Netlify！你的原始想法没错——**只是 Netlify 该放前端，而不是放服务器。**
</details>

<details>
<summary><b>为什么不能直接用 Docker 镜像？</b></summary>

免费主机是 Pterodactyl 类的容器面板，**不支持 Docker**，只能跑原生 Node.js 进程。

所以需要 `build-bundle.sh` 在本地编译一次。这也顺便解决了「官方只发源码不发产物」的问题。
</details>

<details>
<summary><b>服务会被删吗？</b></summary>

Silly Development：**只要 7 天内用过就不会删**（官网原文："a server never used at all in its first 7 days is removed"）。正常使用就不会。

Bot-Hosting：每 4 天必须手动续期，否则删除。
</details>
